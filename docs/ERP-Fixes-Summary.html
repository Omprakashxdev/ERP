Phase 1 — File Uploads & Vehicle Dropdown

Fix 1: Vehicle Dropdown Empty in Journey Log Form

Vehicle dropdown showed no options FIXED

When on the "Journeys" tab, the vehicle dropdown in the Journey Log form was empty. Fixed by ensuring all registered vehicles are loaded for the dropdown regardless of active filters.
How to Test:
  1. Go to Vehicle Log Book → click the "Journeys" tab
  2. Click "New journey log" button
  3. Click the Vehicle dropdown — it should show all registered vehicles by registration number
  4. Select a vehicle — the name should remain visible (not convert to an ID code)
Fix 2: Manual File Path Inputs Replaced with Browse/Upload

FileUploadField component integrated across all forms FIXED

All manual text input fields for file paths have been replaced with a browse/upload button. Users can now select files directly from their computer instead of typing file paths manually. The system uploads the file to the server and stores the path automatically.
How to Test:
  1. Vehicle Form: Go to Vehicle Log Book → Vehicles tab → New vehicle → scroll to R.C./Insurance/P.U.C fields → click "Browse" → select a PDF/image → file path appears automatically
  2. Journey Log Form: Go to Vehicle Log Book → Journeys tab → New journey log → scroll to "Attach photo / document" → click Browse → select file → it appears in the list below with a remove (✕) button
  3. Tender Form: Go to Tenders → New tender → scroll to "Advertisement copy" → click Browse → select file
  4. In-Out Register Form: Go to In-Out Register → New entry → scroll to "Attach document" → click Browse → file added to list with view (↗) and remove (✕) buttons
  5. Supported file types: PDF, JPG, JPEG, PNG, DOC, DOCX, XLS, XLSX (max 10 MB)

Phase 2 — Dropdowns, Uploads, Bulk Import & Reports

Fix 3: Dropdowns Showing Codes Instead of Names

SelectValue displaying entity IDs (CUIDs) instead of human-readable names FIXED

When selecting a name, client, staff member, or project from any dropdown, the selection was converting into a long code/ID string instead of showing the readable name. Fixed across all forms and filter bars so that dropdowns always display human-readable names.
How to Test:
  1. Go to WIP → click any existing record to edit → the Project, HO coordinator, and RO coordinator dropdowns should show the selected entity's name, not a long ID string
  2. Go to Fund Flow → open a project → Region and Client dropdowns should show names
  3. Go to Due Bills → use the filter bar → select a Region/Client/Project → the dropdown should show the selected name
  4. Go to In-Out Register → use filters → select "From/To" (client) and "Action suggested" (staff) → names should display
  5. Go to TADA Bills → create or edit a claim → the Employee dropdown should show the staff name when selected
Fix 4: Document Upload Not Working on Server

Upload directory permissions and server environment FIXED

The upload directory on the production server had incorrect permissions preventing file writes. Fixed directory ownership, created module-specific subdirectories, and corrected the server environment configuration.
How to Test:
  1. Go to any form with a file upload field (e.g., Vehicle Form → R.C. copy)
  2. Click Browse → select a file → wait for upload to complete
  3. The file path should appear in the field (e.g., /uploads/vehicle-rc/1234567_document.pdf)
  4. Save the form → verify the file path is stored correctly
  5. For In-Out Register documents, click the ↗ icon to open the uploaded file in a new tab
Fix 5: Client Bulk Import

Bulk import functionality added to Clients page NEW

Added a "Bulk Import" button to the Clients page. Users can download a CSV/Excel template, fill in client data, and upload it to create multiple clients at once. Duplicate client names are automatically detected and rejected.
How to Test:
  1. Go to Clients page (left sidebar → Clients)
  2. Click the "Bulk Import" button (top right, next to page title)
  3. Click "CSV" or "Excel" to download the template
  4. Open the template — it will have columns: name, abbreviation, address
  5. Fill in a few client rows and save the file
  6. Upload the file using the file picker, or paste CSV data directly
  7. Click "Import" — you should see a success message with the count of imported records
  8. The clients list should refresh automatically showing the new clients
  9. Try importing a duplicate client name — it should show an error message
Fix 6: EMD Deposit Refund Data

EMD refund tracking enhanced in Tender Fee – EMD Report ENHANCED

The "Tender Fee – EMD Wise Report" has been enhanced with a Refund Status column that automatically calculates whether EMD is refunded, pending refund, or still in process. The report summary now shows total EMD deposited, total refunded, and total pending refund.
How to Test:
  1. Go to Reports (left sidebar)
  2. Select the "Tenders" category tab
  3. Click the "Tender Fee – EMD Wise Report" card
  4. Click "Generate Report"
  5. Verify the report shows these columns: Date, Tender Name, Tender Fee, Fee Mode, EMD Amount, EMD Mode, EMD Date, EMD Return Date, Refund Status, Tender Status
  6. The Refund Status column should show one of:
    • "Refunded" — if EMD return date is filled
    • "Pending Refund" — if tender is WON/LOST/WITHDRAWN/CANCELLED but no return date
    • "Submitted (in process)" — if tender is still active
    • "—" — if no EMD amount was recorded
  7. Check the summary section shows: Total tender fees, Total EMD deposited, EMD refunded, EMD pending refund
Fix 7: City Uniqueness Validation

Cities must have unique names (case-insensitive) FIXED

When creating or updating a city in the Masters page, the system now checks if a city with the same name already exists (case-insensitive). If a duplicate is found, an error message is shown and the operation is blocked.
How to Test:
  1. Go to Masters page (left sidebar → Masters)
  2. Select the "Cities" tab
  3. Click "New city"
  4. Enter a city name that already exists (e.g., "Surat") and select a state
  5. Click "Create" — you should see an error: "City 'Surat' already exists. City names must be unique."
  6. Try with different case (e.g., "SURAT") — it should still be blocked
  7. Enter a new unique city name — it should be created successfully
Fix 8: Client/Staff Management Pages — Verified

Client and Staff management already available VERIFIED

Clients: Full create, edit, search, and manage functionality available on the Clients page. Bulk import is also available (see Fix 5).

Staff/Employees: Staff are managed through the Fund Flow module. When creating a Fund Flow project, staff can be assigned as coordinators. Staff data is used across WIP, TADA Bills, Tasks, and In-Out Register.
How to Test — Clients:
  1. Go to Clients from the left sidebar
  2. Click "New client" → fill in name, abbreviation, address, and contacts → click "Create client"
  3. The new client should appear in the table
  4. Click the edit (✏) icon to modify → save changes
How to Test — Staff:
  1. Go to Fund Flow → open a project
  2. Staff assignments are visible in the project form
  3. Staff created here are available in WIP, TADA Bills, Tasks, and In-Out Register dropdowns
Fix 9: Interlinking of Clients/Employees — Verified

Clients and Staff are linked across modules VERIFIED

Client linkages:
  • Fund Flow → Projects are linked to Clients (client dropdown in project form)
  • In-Out Register → "From/To (client)" dropdown links to client master
  • Due Bills → Projects (which are linked to clients) are selectable
  • WIP → Projects (which are linked to clients) are selectable
Staff/Employee linkages:
  • WIP → HO coordinator, RO coordinator, and L1–L4 level assignments
  • TADA Bills → Employee selection for travel claims
  • Tasks → Assignee selection
  • In-Out Register → Action suggested staff, CC marked staff
  • Fund Flow → Staff assignments per project
How to Test:
  1. Create a client in Clients page
  2. Go to Fund Flow → create a project → select the client in the Client dropdown
  3. Go to In-Out Register → create an entry → select the client in "From/To (client)" dropdown
  4. Go to WIP → create a record → select the project → assign HO/RO coordinators from staff
  5. Go to TADA Bills → create a claim → select an employee
  6. All dropdowns should show names (not IDs) — see Fix 3
